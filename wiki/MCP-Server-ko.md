# MCP 서버

[English](MCP-Server) · [홈](Home-ko)

---

```
claude mcp add --scope user nekoi_mcp -- /path/to/nekoi_mcp mcp
```

이 한 줄이 설치의 전부입니다. 서버는 표준 입출력으로 JSON-RPC를 주고받으며 세션
내내 살아 있고, 훅이 할 수 없는 세 가지를 합니다 — 집계를 도구로 노출하고, 기록을
계속 따라가고, 자기 훅 등록을 씁니다.

## 프로토콜

프로토콜 버전 `2026-07-28`. `initialize` 응답은 클라이언트가 요청한 버전을 그대로
돌려줍니다. 우리 버전을 고정하면 다른 리비전의 클라이언트와 핸드셰이크가
실패합니다.

```json
{ "protocolVersion": "<요청받은 값>",
  "capabilities": { "tools": { "listChanged": false }, "logging": {} },
  "serverInfo": { "name": "Nekoi_MCP", "version": "1.0.0",
                  "author": "Nekoi", "contact": "garnet@everlib.pro" } }
```

`logging`을 선언하는 이유는 그것이 감시자의 판정을 클라이언트로 보내는
통로이기 때문입니다. `notifications/message`는 서버가 이 capability를 선언했을
때만 처리됩니다.

| 메서드 | 동작 |
| --- | --- |
| `initialize` | 핸드셰이크, capability |
| `tools/list` | 아래 세 도구 |
| `tools/call` | 감시자 pending 검사 후 디스패치 |
| `ping` | 빈 결과 |

`id`가 없는 요청은 알림이며 응답하지 않습니다.

## 도구

| 도구 | 인자 | 반환 |
| --- | --- | --- |
| `censor_session_status` | `session_id` (선택) | 세션 하나의 집계 — EN/JA 횟수, 거부 수, 호출 수, 연속 횟수, 마지막 판정, 감시자 집계, 컨텍스트·출력 토큰, 통지 수, 주입 글자 수, 작업 디렉터리 |
| `censor_sessions` | `limit` (기본 10) | 기록된 세션을 최근 순으로 |
| `censor_check_text` | `text` (필수) | 훅과 같은 규칙으로 글을 판정하고, 찾아낸 영어 문장을 인용하며, 걸리는 금지 패턴을 알려 줌 |

`session_id`를 생략하면 가장 최근에 갱신된 세션을 씁니다.

`censor_check_text`는 위반을 만들지 않고 판정기를 시험해 볼 수 있는 유일한
방법입니다 — 임의의 글에 `lang.Classify`, `lang.EnglishSpans`, `ScanPatterns`를
돌립니다.

## 감시자

훅은 도구 호출 직전과 턴 종료에만 돕니다. 그 사이에 만들어진 사고는 어느 쪽에도
닿지 않습니다. 서버는 모든 훅 실행보다 오래 살아 있으므로, 거기의 고루틴이
기록을 따라가며 각 블록을 그 자리에서 판정할 수 있습니다.

**폴링.** 300 ms마다 `CLAUDE_DIR/projects/*/` 아래 모든 `*.jsonl`의 크기를 보고,
직전 패스 이후 덧붙은 바이트만 읽습니다. 크기가 줄었으면 파일이 교체된 것이므로
오프셋을 0으로 되돌립니다.

**첫 관측.** 처음 보는 기록은 *판정하지 않고* 오프셋만 현재 크기로 맞춥니다.
이미 디스크에 있던 것은 전부 이 서버가 뜨기 전에 쓰인 것입니다. 지난 세션의 사고를
지금 하려는 호출에 물리는 것은 틀렸고, 기동할 때마다 과거 블록 전체가 한꺼번에
걸립니다.

**부분 줄.** `consume`은 마지막 완전한 줄에서 멈춥니다. 아직 쓰이는 중인 줄은
다음 패스로 넘기므로, 반쯤 쓰인 JSON 레코드를 파싱하는 일이 없습니다.

**적중 시 동작.** 순서대로 — 메모리의 `recent` 링에 추가, 이 프로세스가 처리할
`pending` 저장, 세션 상태 로드, `WatchEN`/`WatchJA`/`WatchSeen` 증가,
`WatchBlock`에 판정과 문제 발췌 기록, 저장, 마지막으로 클라이언트에 알림.

상태를 알림보다 *먼저* 씁니다. 클라이언트가 그 메시지를 무시하더라도 집계와
플래그는 다음 훅을 위해 남습니다.

**소유권.** `Streak`과 `LastVerdict`는 훅의 것입니다 — 턴이 깨끗하게 돌아오면
훅이 초기화하는데, 쓰는 주체가 둘이면 반복 횟수가 틀어집니다. 감시자는 자기
필드만 소유합니다.

### 감시자가 할 수 있는 것과 없는 것

훅이 돌기 전에 판정을 확정하고, 그것을 영속적으로 기록하고, 이 서버 자신의 도구
호출을 거부하고, 클라이언트에 메시지를 밀어낼 수 있습니다.

모델을 멈출 수는 없습니다. 호출을 거부할 수 있는 것은 훅뿐입니다. elicitation은
*서버가 받은 요청을 처리하는 중에* 보내는 것이지 서버가 스스로 시작하는 것이
아니고, `notifications/cancelled`는 구독 스트림을 끊는 용도로 제한됩니다. 그래서
감시자의 역할은 훅이 도는 시점에 판정이 이미 참이 되게 만드는 것, 그리고 뒤늦은
단일 패스가 우연히 잡는 것이 아니라 전량을 기록하는 것입니다.

### 즉시 거부

`callTool`은 디스패치 전에 `TakePending()`을 확인합니다. 마지막 호출 이후
감시자가 위반을 잡았다면, 문제가 된 블록을 인용하며 그 도구 호출을 거부합니다 —
훅은 관여하지 않습니다. pending 플래그는 가져가는 순간 해제됩니다. 세워 둔 채로
두면 이후 모든 호출이 거부됩니다.

### 알림

응답 루프와 감시자가 같은 표준 출력에 쓰므로 모든 쓰기가 하나의 뮤텍스를
지납니다. 두 쓰기가 섞이면 어느 쪽도 파싱할 수 없는 JSON이 나옵니다.

```json
{ "jsonrpc": "2.0", "method": "notifications/message",
  "params": { "level": "error", "logger": "Nekoi_MCP",
              "data": "[WATCH_EN] The transcript watcher read this thinking block as it was written:\n> …" } }
```

`Stop()`은 폴링 고루틴이 끝날 때까지 기다린 뒤 반환합니다. 호출한 쪽이 감시자가
쓰는 연결을 flush하고 닫기 때문입니다.

## 자기 등록

두 모드는 별개 등록입니다. 명령줄의 `mcp`는 서버로, 인자 없음은 훅으로
갑니다. 서버만 등록하면 도구는 얻지만 집행은 하나도 얻지 못합니다.

그래서 기동 시 `selfreg.Ensure`가 `PreToolUse`, `Stop`, `MessageDisplay`에 이
바이너리를 넣습니다 — 자기 경로가 아직 없는 이벤트에만 넣습니다.

- 알 수 없는 최상위 키는 `json.RawMessage`로 들고 있으므로, `hooks` 바깥의
  무엇도 이 왕복으로 다시 쓰이지 않습니다.
- 기존 훅 항목은 통째로 비교하지 않고 안을 들여다봅니다. matcher가 이 패키지가
  모델링하지 않은 필드를 실을 수 있기 때문입니다.
- 경로 비교는 `sig.NormalizePath`를 지납니다. Windows는 두 구분자를 다 받고
  대소문자를 무시하며, 손으로 쓴 항목은 다른 쪽을 썼을 수 있습니다.
- 바뀐 것이 없으면 아무것도 쓰지 않습니다.
- 쓰기는 임시 파일을 거쳐 이름을 바꾸므로, 도중에 실패해도 원래 설정이 남습니다.

실패해도 치명적이지 않습니다 — MCP 도구는 그대로 동작하고 다음 기동에서 다시
시도합니다.
