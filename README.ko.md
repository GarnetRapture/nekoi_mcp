# Nekoi_MCP

Claude Code가 도구를 부르기 직전에 그 호출의 사고 원문을 읽고, 규칙에 어긋나면 호출을 막습니다.

실행 파일은 하나지만 동작 방식은 2가지입니다. 하나는 편집기가 도구 호출과 턴 종료마다 실행하는 훅이고, 다른 하나는 세션에 쌓인 기록을 들여다보는 MCP 서버입니다.

## 무엇을 막아주나

무엇을 막을지는 세션 기록에 남은 모델의 실제 출력을 보고 정합니다. 짐작으로 판단하지 않습니다.

막는 항목은 모두 6가지입니다.

**첫째, 사고 언어입니다.** 사고 블록은 한국어로 써야 합니다. 먼저 코드 식별자와 경로, 백틱으로 감싼 부분을 걷어냅니다. 그다음 남은 문장을 하나씩 봅니다. 한글이 하나도 없고, 알파벳 단어가 3개 이상이며, 기능어까지 들어간 문장이라야 영어로 셉니다. 이렇게 센 영어 문장이 한국어 문장보다 많아야 걸립니다. 그래서 식별자나 외래어가 몇 개 섞였다고 잡히지는 않습니다. 한 번 지적한 블록은 커서가 지나가므로 다시 걸리지 않습니다.

**둘째, 사고 절차입니다.** 파일을 고치기 전에 다음 4가지가 정리돼 있어야 합니다. 원인이 무엇인지, 무엇을 지적받았는지, 이 둘을 합치면 어떤 결론이 나오는지, 그 결론대로 하려면 어떤 순서를 밟아야 하는지입니다. 이 가운데 2개 이상이 비어 있으면 호출을 거부합니다. "일단 해보자"는 상태로 파일을 건드릴 때, 그리고 이미 손을 댄 뒤에 무엇이 확정됐는지 말하지 않고 또 분석에 들어갈 때도 막습니다.

**셋째, 낭비 호출입니다.** 이번 턴에 이미 돌린 것과 똑같은 호출을 막습니다. 세션 안에서 이미 확인이 끝난 프로그램의 설치 여부나 버전을 또 묻는 것도 막습니다. 지시 하나에 35번을 넘겨 조사만 이어가도 걸립니다.

**넷째, 도구 선택입니다.** ADB가 아닌 일에 PowerShell을 쓰면 막습니다. `python`을 써야 할 자리에 `python3`을 쓰거나, `jq`를 써야 할 자리에 Python `json` 모듈을 쓸 때도 마찬가지입니다. Edit 대신 Python으로 파일을 읽고 쓰는 것, 드라이브 최상위에 파일을 떨어뜨리는 것, `head`나 `tail`, `sed -n`, 슬라이싱으로 데이터를 잘라놓고 결론을 내는 것도 모두 막습니다.

**다섯째, 보고입니다.** 이번 턴에 열어보지도 않은 파일을 근거인 양 인용할 때 막습니다. 명령을 돌리지도 않고 그 출력을 옮겨 적을 때, Edit을 한 번도 부르지 않고 다 고쳤다고 보고할 때, 확인된 것과 확인되지 않은 것을 나눠서 넘길 때도 막습니다.

**여섯째, 턴 종료입니다.** 도구를 한 번도 부르지 않은 채 형식적인 말로 끝내거나, 사용자에게 되물으며 끝내면 막습니다.

패턴은 `thinking.json`에 모아 뒀습니다. 정규식과 부정 정규식, 그리고 주입할 메시지로 이뤄지며 부정 정규식은 없어도 됩니다. 기본 패턴은 실행 파일 안에 들어 있습니다. `~/.claude/thinking.json`이나 `CENSOR_PATTERNS`가 가리키는 파일을 두면 다시 빌드하지 않고도 그 파일을 대신 씁니다.

## 토큰 제어

한 번 주입한 내용은 그 세션이 끝날 때까지 요청을 보낼 때마다 계속 값을 치릅니다. 그래서 프롬프트가 커질수록 주입할 수 있는 양을 줄여 나갑니다. 이때 크기는 기록에 남은 API 사용량을 그대로 읽어서 쓰며, 글자 수로 어림잡지 않습니다.

| 컨텍스트 토큰 | 주입 상한 |
| --- | --- |
| 8만 미만 | 700자 |
| 8만 ~ 20만 | 460자 |
| 20만 ~ 40만 | 320자 |
| 40만 초과 | 220자 |

220자 아래로는 줄이지 않습니다. 무슨 일이 있었고 무엇을 해야 하는지조차 담지 못하면 토큰만 쓰고 달라지는 게 없기 때문입니다. 같은 위반을 두 번 자세히 알린 다음부터는 한 줄과 문제가 된 문장 하나만 보냅니다. 자세한 설명은 앞서 보냈으니 대화에 그대로 남아 있습니다.

## 설치

빌드해 둔 실행 파일이 `dist/` 폴더에 함께 올라가 있습니다. Go를 따로 깔지 않아도 자기 운영체제에 맞는 파일을 내려받아 바로 쓰면 됩니다. Linux나 macOS에서는 내려받은 뒤 `chmod +x`로 실행 권한을 주십시오.

직접 빌드하려면 이렇게 합니다.

```
git clone https://github.com/GarnetRapture/nekoi_mcp
cd nekoi_mcp
make            # 또는: go build -o nekoi_mcp ./cmd
```

`make`를 실행하면 아래 4가지 실행 파일이 `dist/` 폴더에 만들어집니다. Windows용을 만들 때만 아이콘과 버전 정보 때문에 `windres`(MinGW)가 더 필요하고, 나머지는 Go 툴체인만 있으면 됩니다.

| 명령 | 만들어지는 파일 |
| --- | --- |
| `make windows` | `dist/windows-amd64/nekoi_mcp.exe` |
| `make linux` | `dist/linux-amd64/nekoi_mcp` |
| `make darwin` | `dist/darwin-amd64/nekoi_mcp` |
| `make darwin-arm64` | `dist/darwin-arm64/nekoi_mcp` |

## 등록

MCP 서버로 등록하려면 이렇게 합니다.

```
claude mcp add --scope user nekoi_mcp -- /path/to/nekoi_mcp mcp
```

이 한 줄이 설치의 전부입니다. 훅은 따로 넣지 않아도 됩니다. 서버가 처음 뜰 때 `~/.claude/settings.json`을 열어 `PreToolUse`, `Stop`, `MessageDisplay` 가운데 자기 실행 경로가 없는 것에만 자기를 넣습니다. 이미 들어 있으면 파일을 건드리지 않고, 나머지 설정과 다른 훅 항목은 원문 그대로 둡니다. 쓸 때는 임시 파일에 먼저 적고 이름을 바꾸므로, 도중에 실패해도 원래 설정이 남습니다.

같은 실행 파일이 두 가지로 동작합니다. 아무 인자 없이 실행하면 훅으로 돌면서 표준 입력으로 들어온 내용을 읽고, 뒤에 `mcp`를 붙이면 표준 입출력으로 JSON-RPC를 주고받습니다. 위 등록은 `mcp`를 붙이므로 서버 쪽이고, 훅 쪽은 인자 없이 불립니다.

`MessageDisplay`는 답변이 화면에 흐르는 동안 돌아갑니다. 사고 블록은 화면에 그려지기 전에 이미 JSONL에 적히므로, 이 시점이면 방금 쓴 사고를 그 자리에서 읽을 수 있습니다. 여기서 위반이 잡히면 그 답변을 중간에 끊습니다. `PreToolUse`와 `Stop`만 걸려 있으면 도구를 부르지 않고 사고만 이어가는 구간이 통째로 비어 버립니다.

## MCP 도구

| 도구 | 하는 일 |
| --- | --- |
| `censor_session_status` | 세션 하나의 집계를 보여 줍니다. 언어 위반과 거부 횟수, 호출 수, 연속 횟수, 컨텍스트 크기가 나옵니다 |
| `censor_sessions` | 기록된 세션을 최근 것부터 늘어놓습니다 |
| `censor_check_text` | 훅과 같은 규칙으로 글을 판정하고, 걸리는 패턴을 알려 줍니다 |

## 설정

| 변수 | 기본값 | 용도 |
| --- | --- | --- |
| `CLAUDE_DIR` | `~/.claude` | 설정이 모여 있는 최상위 폴더 |
| `CENSOR_PATTERNS` | `$CLAUDE_DIR/thinking.json` | 패턴 파일. 없으면 실행 파일에 든 기본 패턴을 씁니다 |

세션마다 남는 상태는 `$CLAUDE_DIR/state/censor/` 아래에 JSON 파일 하나씩 쌓입니다.

## 구조

```
cmd/                 훅 모드, MCP 서버, 빌드 리소스
internal/lang/       문장 단위 언어 판정
internal/transcript/ JSONL 파싱, 사용량 집계
internal/session/    세션별 상태
internal/sig/        도구 호출·환경 조회 식별자
internal/rules/      규칙, 주입 예산, 내장 패턴
internal/watch/      세션 기록 실시간 추적
internal/selfreg/    훅 자동 등록
```
